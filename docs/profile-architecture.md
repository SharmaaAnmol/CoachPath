# Central Career Profile & Evidence Graph Architecture (Phase 3C)

## 1. Architectural Role & Objective

In CoachPath, the **Career Profile** is the central, authoritative source of structured career information and verified evidence for candidate users. All downstream modules—such as Onboarding (Phase 4), Resume Ingestion & Truthful Tailoring (Phase 5 & 11), Diagnostic Assessments (Phase 6), Skill-Gap Analysis (Phase 7), Dynamic Roadmaps (Phase 8), and Semantic Job Matching (Phase 10)—depend directly upon this unified ground truth.

## 2. Master Data Model & Ground-Truth Invariant

### 2.1 Persistent Relational Domain (`app/models/career.py`)
1. **`User` & `UserProfile`**: Stores account credentials, full name, headline, location, contact information, portfolio URLs, and executive biography.
2. **`CareerProfile`**: 1:1 relationship with `User`. Stores:
   - `primary_role_id` (Foreign key to canonical benchmark `roles.id`)
   - `secondary_role_id` (Optional secondary exploration role)
   - `career_stage`: `'student'`, `'recent_graduate'`, or `'early_career'`
   - `work_preference`: `'remote'`, `'hybrid'`, `'onsite'`, or `'flexible'`
   - `target_locations`: Stored as PostgreSQL JSON array
   - `years_of_experience`: Numeric decimal precision
3. **`Education`**: Scoped to `career_profiles.id`. Captures institution, degree, field of study, start date, end date, is_current flag, and numerical GPA (0.00 – 4.00).
4. **`Experience`**: Scoped to `career_profiles.id`. Captures company, role title, location, date bounds, is_current, and structured impact bullet points (JSON array).
5. **`Project`**: Scoped to `career_profiles.id`. Captures title, technical description, technologies used (JSON array), repository GitHub URL, live demo URL, and technical accomplishments.
6. **`Certification`**: Scoped to `career_profiles.id`. Captures credential name, issuing organization, issue date, expiration date, credential ID, and public verification link.

### 2.2 Strict Invariant: User-Provided vs. System-Derived Data
- **User-Provided Information**: Personal details, career targets, manual work history, academic credentials, and project links entered or edited directly by the candidate.
- **System-Derived Information**: Diagnostic assessment test results, verified skill proficiency tiers, vector embeddings, and semantic match rankings.
- **Audit Invariant**: System processes (including upcoming Phase 5 resume parsers) may **never** overwrite verified assessment results or approved user entries without explicit human confirmation.

## 3. Deterministic Profile Completeness Engine

CoachPath explicitly rejects non-deterministic or hallucinated completeness scores generated by LLM prompts. Completeness is calculated synchronously using a transparent, weighted 100-point formula implemented in `app/services/profile.py:calculate_profile_completeness`:

$$\text{Completeness} = S_{\text{personal}} + S_{\text{goals}} + S_{\text{education}} + S_{\text{experience}} + S_{\text{projects}} + S_{\text{certifications}}$$

| Category | Maximum Points | Criteria & Point Breakdown |
| :--- | :---: | :--- |
| **Personal Details** | **20 pts** | • Full Name provided: $+5$<br>• Professional Headline: $+5$<br>• Location specified: $+5$<br>• Bio or external profile link: $+5$ |
| **Career Goals** | **20 pts** | • Primary Target Role chosen: $+10$<br>• Career Stage calibrated: $+5$<br>• Work Preference or target locations: $+5$ |
| **Academic Education** | **20 pts** | • At least 1 validated degree / institution record: $+20$ |
| **Work Experience** | **20 pts** | • At least 1 employment / internship record: $+20$ |
| **Technical Projects** | **15 pts** | • At least 1 project / repository artifact: $+15$ |
| **Certifications** | **5 pts** | • At least 1 verified certificate or credential: $+5$ |
| **Total Baseline** | **100 pts** | **Deterministic, repeatable score bounded between 0.0% and 100.0%** |

## 4. RESTful API Contract (`/api/v1/profile`)

All endpoints require candidate authentication via Bearer token or HttpOnly session cookie (`get_current_user` dependency). Cross-user operations are forbidden (403 Forbidden).

### 4.1 Master Aggregation & Personal Metadata
- `GET /api/v1/profile`: Returns `CareerProfileMasterResponse` consolidating candidate identity, primary/secondary benchmark roles, workplace preferences, all evidence collections, verified skill count, and completeness score.
- `PUT /api/v1/profile`: Accepts `UserProfileUpdate` to update name, headline, location, phone, links, and bio.

### 4.2 Benchmark Target Calibration
- `GET /api/v1/profile/career-goals`: Retrieves active primary and secondary target roles and workplace preferences.
- `PUT /api/v1/profile/career-goals`: Calibrates benchmark targets (`CareerGoalsUpdate`).
- `GET /api/v1/profile/roles`: Lists all supported canonical benchmark roles (`backend-developer`, `frontend-developer`, `fullstack-developer`, `ai-engineer`, etc.).

### 4.3 Scoped Evidence Graph CRUD
| Domain | GET (List) | POST (Create) | PUT (Update) | DELETE (Remove) |
| :--- | :--- | :--- | :--- | :--- |
| **Education** | `GET /profile/education` | `POST /profile/education` (201) | `PUT /profile/education/{id}` | `DELETE /profile/education/{id}` (204) |
| **Experience** | `GET /profile/experience` | `POST /profile/experience` (201) | `PUT /profile/experience/{id}` | `DELETE /profile/experience/{id}` (204) |
| **Projects** | `GET /profile/projects` | `POST /profile/projects` (201) | `PUT /profile/projects/{id}` | `DELETE /profile/projects/{id}` (204) |
| **Certifications**| `GET /profile/certifications`| `POST /profile/certifications` (201)| `PUT /profile/certifications/{id}`| `DELETE /profile/certifications/{id}` (204)|

## 5. Multi-Tenant Authorization & Cross-User Isolation

To prevent Insecure Direct Object Reference (IDOR) attacks:
1. Every write operation looks up the candidate's active `CareerProfile` via their authenticated `current_user.id`.
2. When modifying an existing record (e.g. `PUT /profile/education/{id}`), the service verifies:
   $$\text{record.career_profile_id} == \text{current_candidate_career_profile.id}$$
3. Any mismatch immediately aborts the transaction with `HTTP 403 Forbidden` (`INSUFFICIENT_PERMISSIONS`).
4. Automated integration test `test_cross_user_isolation_prevented` continuously guarantees cross-tenant isolation.

## 6. Frontend Architecture & Design System Alignment

The Next.js 14 frontend connects cleanly via `ProfileClient` (`frontend/src/lib/profile-client.ts`):
- **`CareerProfilePage` (`/career-profile` & `/profile`)**:
  - Banner displaying real candidate name, verified status badge, target role, and real profile completeness %.
  - Deterministic Completeness Engine breakdown visualization.
  - Reactive modals for editing personal details, calibrating benchmark roles, and adding/editing/deleting experience, projects, education, and certifications.
  - Zero-state handlers with actionable calls-to-action (`EmptyState`).
  - Export Graph button delivering instant JSON export of the candidate's evidence graph.
- **`DashboardPage` (`/dashboard`)**:
  - Greets the candidate by real name, reflects active benchmark target role, and dynamically reports real completeness %.
